# 触摸协议：引擎反汇编与 M1 实测（2026-11-23）

本文记录从荣耀车联 CarLife 引擎（`com.baidu.carlife.honor`，8.8.5 / versionCode 274）APK 反汇编得到的**多指触摸协议**，以及 M1 预览环境下的实测结论。

> 分析素材：从手机 `pm path` 拉取的 `base.apk`（109MB，仅本地分析用，不入库、不分发），`dexdump -d` 反汇编 + dex 静态字段值提取。

## 3. 引擎 `CarlifeTouchManager` 行为要点

- `dispatchTouchEvent(int serviceType, CarlifeCmdMessage)`：按 serviceType 解析对应 proto 后调用
  `onActionDownEvent/onActionMoveEvent/onActionUpEvent/onActionPointerDown/onActionPointerUp`。
- `onActionMoveEvent(x, y, pointerX, pointerY)`：若已有第二指（`secondDownPointerCoord != null`），
  构造 **2 指 MotionEvent**（pointer0 = x,y；pointer1 = pointerX,pointerY）并通过
  `Instrumentation.sendPointerSync` 注入 UI；否则构造 1 指事件。
- `onActionPointerDown/Up` 受 `isPointerScalingForbidden()` 与 `isErrorTouchModel` 保护：
  - `isPointerScalingForbidden()`：取当前 `vehicleChannel`，若在 `pointerScalingForbiddenList` 内则禁用
    指针缩放（多指）；列表来自车辆配置，普通连接下为空。
  - `isErrorTouchModel`：引擎自检发现异常触摸数据后会短暂拒绝事件。
- 复合动作（0x68001）按 `action & 0xFF` 分发：
  - 0 → DOWN；1 → UP；2 → MOVE(x,y,pointerx,pointery)；
  - 5 → POINTER_DOWN（pointer index 在 action 高字节）；6 → POINTER_UP；
  - 其它 → `onActionOther`。
  该路径的 x/y/pointerx/pointery 全部由 HU 提供，理论上可一次携带完整两指状态。

## 4. M1 实测结论（2026-11-23 修正版）

- **单指点击/拖动正常**：点击音乐播放按钮可开始播放（引擎回调媒体音频格式宣告 + 首包），
  单指拖动地图会平移并出现比例尺。
- **原生多指在真实地图 App 里可用（最终结论）**：
  - CarLife **首页的「地图卡片」**只是预览卡片，不响应捏合——该界面只有「双击后按住上下拖动」缩放；
  - 但用 CarLife 打开 **百度地图 App** 后，不勾选「捏合翻译」直接双指捏合**可以正常缩放**
    （用户实测；日志为 `mode=CPTCL` 的 `0x6800B / 0x68004 / 0x6800D` 序列，无「兼容模式」行）；
  - 结论：**引擎多指协议 + 真实 App 的捏合支持都成立**，之前的失败是测试目标选错了（测的是首页
    地图卡片，不是真正的地图 App）。「捏合翻译」仅保留为不支持捏合的界面（如首页卡片）的兜底方案。
- 因此「多指缩放」在 CarLife 侧的正确落地方式是**翻译**：把双指捏合翻译成
  CarLife 自带的「双击 + 按住上下拖」缩放手势（`捏合翻译` 模式），而不是依赖原生多指。
- **踩坑**：
  1. App 内「自测捏合」最初固定在屏幕正中合成，而正中恰好被 CarLife「搜索目的地」面板遮挡，
     面板不响应地图手势，导致自测始终无效；现已把自测锚点改到 `(w*0.72, h*0.30)` 的地图空白区，
     并交替做「张开/捏合」两种变体；
  2. 捏合翻译合成双击时，第一击抬起点与第二击按下点必须落在**同一点**，否则引擎的双击判定
     不成立（曾相差 200+ px 导致失败）；
  3. 引擎对**多指事件**有 `isPointerScalingForbidden()`（按车辆 `vehicleChannel` 配置禁用指针缩放）
     与 `isErrorTouchModel` 保护，普通连接下均为 false。
- **触摸坐标域**：视频 1280×720，App 内按 `view` 尺寸线性映射到 target；实测点击/拖动坐标一致。

## 5. 工程落地

- `carlife/CarLifeProtocol.kt`：`TOUCH_POINTER_DOWN/UP/OTHER_POINTER_UP`、`touchPointDual(x,y,pointerX,pointerY)`。
- `carlife/CarLifeHuClient.kt`：`touchPointerDown/touchPointerUp/touchOtherPointerUp/touchMoveDual`
  （`enqueueTouch` 支持 4 字段负载）——协议层已具备多指能力，留给未来支持捏合的 CarLife 版本/界面。
- `MainActivity.kt`：
  - 默认 `CPTCL 管线`：单指 DOWN/MOVE/UP；双指 `0x6800B/0x68004/0x6800C/0x6800D`（原生多指，
    百度地图等真实 App 可用）；
  - `捏合翻译`（默认关）：双指捏合 → 第一击 + 100ms 后第二击按住 + 按捏合量上下拖动；
    仅用于不支持捏合的界面（CarLife 首页地图卡片）兜底；
  - 保留 `模式B`/`新触摸` 实验开关。
- `CarLife 首页卡片缩放 = 双击 + 按住上下拖`：翻译方向约定「张开→上拖（放大）、捏合→下拖（缩小）」，
  系数 `TRANSLATE_GAIN = 1.5`，方向反了改负。

## 6. 对 AA 桥（M2/M3）的意义

CarLife 侧原生多指已实测可用，桥接层只需做**事件直通**：

- 单指：AA 触摸 → CarLife 单指消息（点击/拖动/双击缩放直接可用）；
- 双指：AA 的 `ACTION_POINTER_DOWN/MOVE/UP` → `0x6800B/0x68004/0x6800C/0x6800D`（坐标直通）；
- 兜底：若某些界面（如 CarLife 首页卡片）不支持捏合，可再走「捏合翻译」合成双击拖动；
- 前提：MIB3 的 AA 触摸通道需要上报第二根手指（CarPToCarL 固件分析称车机 HID 只报单指，待实车验证）。
