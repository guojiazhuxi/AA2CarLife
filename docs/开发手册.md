## 0. 先读这一页

**你要做的东西**：一个装在荣耀手机上的 App，同时扮演两个角色——

- 对车机（奥迪 MIB3，有线 AA）：一台"跑着 Android Auto 的手机"（USB AOA accessory）；
- 对本机荣耀车联/CarLife+：一台"支持无线 CarLife 的车机"（连本机 7240 等 7 个端口，劫持 H.264/PCM）。
- 中间把 CarLife 的 H.264 直通进 AA 视频通道，把 AA 触摸映射成 CarLife 的触控动作。

**开发顺序（重要）**：先做 M1（CarLife 单侧，只需手机+车机蓝牙）→ M2（AA 单侧，PC 台架，无需车和证书）→ M3（台架桥接）→ M4（上车，需 Google 证书）→ M5（体验）。**M1–M3 全程不需要车、不需要 Google 证书。**

**参考实现**：
- CarLife 侧：[CarPToCarL](https://github.com/jjuugk/CarPToCarL)（MIT）——它的 `CarLifeProtocol.kt` 就是你要的协议常量/帧编解码，可直接复制；
- AA 侧：[AARE](https://github.com/prototux/AARE)（GPL-3.0）——`aap/` 是纯 Kotlin/JVM 的 AA 协议层（分帧/TLS/会话/通道/测试），直接 vendor；
- 对照：[HSD](https://github.com/SadykovIV/HSD)（多协议发送端）、[mretallack/AndroidAuto](https://github.com/mretallack/AndroidAuto)（最小实现）。

### 2.4 语言选择：为什么用 Kotlin（Java 行不行）

| 问题 | 回答 |
|---|---|
| Android App 只能用 Java 写吗？ | 不是。**Java 和 Kotlin 都可以**，两者最终都编译成 JVM 字节码 → D8/R8 → dex，跑在 ART 上，运行效果一样 |
| 为什么本项目用 Kotlin？ | 参考实现（AARE、CarPToCarL、HSD）**全是 Kotlin**，移植/对照最省力；协程/Flow 写协议状态机更顺手；Android Studio 新建工程默认 Kotlin（Google 2019 起 Kotlin-first） |
| Java 行不行？ | 行。Java 与 Kotlin **100% 互操作**：Java 代码可以调用 Kotlin 模块（反过来也一样）。但你要照着 Kotlin 源码移植 AARE/CarPToCarL 的部分会更费劲 |
| 要写 C/C++ 吗？ | 不需要。AARE 已证明纯 Kotlin 能完成 AA 手机端（H.264 走 `MediaCodec` 硬编解码）。只有在追求极致性能/复用 C++ 库时才用 NDK，本项目不需要 |
| UI 用什么？ | 本项目建议经典 View（`SurfaceView`）+ XML，不引入 Compose，减少依赖和构建时间；Java/Kotlin 都能写 |

> 结论：**按 Kotlin 走**。如果你更熟 Java，自研的 `bridge/`、`ui/` 可以用 Java 写，不冲突；但 vendored 的 AARE/CarPToCarL 代码保持 Kotlin 原样最省事。

## 3. 模块开发指南

### 3.1 transport：USB AOA 与台架 TCP

**USB AOA 时序**（车机是 host）：`51 GET_PROTOCOL` → `52 SEND_STRING`×(manufacturer/model/description/version/URI/serial) → `53 START` → 手机重枚举为 `18D1:2D00` → 系统发 `USB_ACCESSORY_ATTACHED` → App 拿 `UsbAccessory` → `openAccessory()` → `getFileDescriptor()` → 自己 read/write。

**Manifest**：

```xml
<uses-feature android:name="android.hardware.usb.accessory" android:required="true" />

<activity android:name=".MainActivity" android:exported="true">
  <intent-filter>
    <action android:name="android.hardware.usb.action.USB_ACCESSORY_ATTACHED" />
  </intent-filter>
  <meta-data android:name="android.hardware.usb.action.USB_ACCESSORY_ATTACHED"
             android:resource="@xml/accessory_filter" />
</activity>
```

```xml
<!-- res/xml/accessory_filter.xml：先用实测六串填；拿不到时用 AARE 日志 / adb shell dumpsys usb 取 -->
<resources>
  <usb-accessory manufacturer="Android" model="Android Auto" />
</resources>
```

**transport 接口**（自研，约 100 行）：

```kotlin
interface Transport {
    fun open(): Boolean          // 拿 fd / 建 socket
    fun read(buf: ByteArray): Int
    fun write(buf: ByteArray, len: Int)
    fun close()
    val connected: Boolean
}
```

**实现要点**：

- `openAccessory()` 返回 `UsbDeviceConnection`，用 `connection.fileDescriptor` 包 `ParcelFileDescriptor` → `FileInputStream/FileOutputStream`；
- **accessory 模式没有 UsbEndpoint，不要用 `bulkTransfer`**；
- 读线程阻塞读，写完 `flush`；读到 `0/-1` 视为断开 → 状态机重连；
- 前台服务类型 `connectedDevice`（Android 14+ 需 `FOREGROUND_SERVICE_CONNECTED_DEVICE` 权限）；
- 荣耀的"USB 用途"弹窗可能抢焦点，App 内给引导文案即可。

**台架 TCP**：实现一个 `head-unit-server` 模式——在 `127.0.0.1:5277`（或 local abstract）监听，自己当 AA "车机端"的 TCP 对端。这样 PC 可以用 `adb forward tcp:5277 tcp:5277`（或 AARE headunit 的 `--adb-target tcp:5277`）连上来，**不需要真车**。

> ⚠️ 调试通道仅 debug 包/设置页显式开启，且默认只绑 `127.0.0.1`；不要对局域网开放（AARE 默认一次会话后关闭网络模式，就是出于安全考虑）。

### 3.2 aap：AA 协议层（vendor 自 AARE）

**不要从零写**。AARE 的 `aap/` 已经把分帧、TLS 1.2、版本协商、服务发现、通道管理、模拟器、单元测试都做好了。步骤：

1. 复制 `refs/AARE/aap/` 下的 `src/main/kotlin`、`src/main/proto`、`build.gradle.kts` 到你的 `app/src/main/java/.../aap/`（或独立 module），改包名；
2. 保留 `aap/src/main/proto/NOTICE.md`；
3. 跑 `aap` 自带测试（如果有 JVM test）确认移植成功；
4. 在 App 里只使用它的 **会话/通道 API**，不要改协议内部实现。

**你必须知道的 AA 事实**（照抄即可，细节以 AARE 实现为准）：

| 项 | 值 |
|---|---|
| 传输 | USB AOA v2（或 TCP，台架） |
| TLS | 1.2，**手机 = TLS server**，双向认证；用 `SSLEngine`（fd 不是 Socket，不能用 `SSLSocket`） |
| 证书 | 自签 RSA-2048；M4 换成 Google 签发证书（可导入/替换） |
| 控制消息 ID | 1 版本请求 / 2 版本响应 / 3 SSL 封装 / 4 认证完成 / 5 服务发现请求 / 6 服务发现响应 / 7 通道打开请求 / 8 通道打开响应 / 9、10 ping …（以 AARE `aap` 源码为准） |
| 认证状态 | 0 成功 / -3 失败 / -23 未生效 / -24 过期（由**车机**在 AUTH_COMPLETE 返回） |
| 视频 | H.264；首帧前先发 VideoConfig（SPS+PPS）；焦点恢复必须等新 IDR |
| 输入 | 坐标域 = **视频像素**；含 touch/key/rotary；要处理 pointer count |
| 服务声明 | 首版只声明 video + input（+ sensor 可选）；别声明没实现的 audio |

**证书加载**（Kotlin 示意）：

```kotlin
val ks = KeyStore.getInstance("PKCS12").apply {
    load(context.assets.open("aa_self.p12"), "changeit".toCharArray())
}
val kmf = KeyManagerFactory.getInstance(KeyManagerFactory.getDefaultAlgorithm())
kmf.init(ks, "changeit".toCharArray())
val ctx = SSLContext.getInstance("TLSv1.2").apply {
    init(kmf.keyManagers, arrayOf(trustAllTm), SecureRandom())
}
val engine = ctx.createSSLEngine().apply {
    useClientMode = false       // 手机是 server
    needClientAuth = true
    beginHandshake()
}
```

> `trustAllTm` 只用于台架/个人自用；**把车机证书的 subject/issuer 打进日志**，方便判断 MIB3 用的是哪套证书。

**TLS 与帧的衔接**：`SSLEngine` 的 `wrap/unwrap` 输出再按 AAP 帧封装（channel 0 / type 3）；不要自己发明帧格式——用 AARE 的 framer。

### 3.3 carlife：CarLife 车机端（移植自 CarPToCarL）

**这是本项目最确定的一块**：协议常量、端口、时序、字段、触控、音频都在 `CarLifeProtocol.kt` 里，直接移植（MIT，保留声明）。

**端口**：`7240` 主 / `8240` 视频 / `9240` 媒体音频 / `9241` TTS / `9242` VR / `9340` 触控 / `9440` data。

**握手（必须按这个顺序）**：

```
98305 (协议 3.0: pbVarint(1,3)+pbVarint(2,0))     →  65538 matchStatus==1
98343 统计信息                                     →  65563/65540/65574
98307 HU_INFO（字段序严格）                        →  （等 65574 后回 98344）
98386 featureConfig（CONTENT_ENCRYPTION=0, DISABLE_RESOLUTION_OPTION=1, I_FRAME_INTERVAL=20）
98311 videoEncoderInfo(width,height,fps[, saveArea, needAdapterScreen])
                                                    →  65544
98313 VIDEO_ENC_START                               →  8240 开始 H.264
每 1s: 131074 心跳
```

**HU_INFO 字段序（错一位就静默断链）**：
`os, board, bootloader, brand, cpuAbi, cpuAbi2, device, display, fingerprint, hardware, host, cid, manufacturer, model, product, serial, codename, incremental, release, sdk, token, btaddress, carlifeversion`（另有 `sdkInt` 整型）。

**帧格式（大端）**：
- 控制通道（channel 1 / 6）：`[u16 len][u16 rsv][u32 serviceType]`（8B 头）
- 其他通道：`[u32 len][u32 seq][u32 serviceType]`（12B 头）
- 视频通道 `8240`：SPS/PPS/IDR/P 的 Annex-B NAL。

**触控（9340）**：
- 单点：`0x68002/3/4`（DOWN/UP/MOVE），负载 `{x, y}`
- 双指：**必须走 `0x68001` 复合动作**，`action = MotionEvent码 | (pointerIndex shl 8)`，`POINTER_DOWN=5 / POINTER_UP=6`；单点消息没有指针概念，第二根手指表达不出来（这是"捏不动"的根因）。
- 坐标域 = 编码视频像素；**原样透传，不替引擎做 offset 换算**。

**音频**：
- 媒体（9240）：12B 头 `[len][timestampMs][pkgType]` + PCM；`INIT=0x30001` / `NORMAL=0x30006` / `PAUSE=0x30003` / `RESUME=0x30004`
- TTS（9241）：`0x40001/0x40002/0x40003`
- 采样率经 `98386` 的 `MEDIA_SAMPLE_RATE` 宣告（1=48k，其它=44.1k）

**错误恢复（必须实现）**：
- 收 `65642`（EncryptSetup）→ 说明进了加密路径 → 立刻中止并提示重启引擎（`am force-stop com.baidu.carlife.honor`，需用户手动/Shizuku）；
- 发 `98311` 后 2–3 s 内没 `65544` → 检查引擎是否在"正在连接"、协议是否 3.0、featureConfig 是否带 `CONTENT_ENCRYPTION=1`；
- 引擎进程级 `isNewVehicleVersion` 污染只能重启进程解除。

**版本锁**：实测基线是荣耀 `com.baidu.carlife.honor` **8.8.5 / versionCode 274**；升级后重验（`65538`/`65642` 行为），App 里显示版本号并提示兼容性。

### 3.4 bridge：桥接层（自研，核心）

| 子模块 | 职责 | 关键点 |
|---|---|---|
| `ResolutionAligner` | AA 协商的分辨率 → 通过 98311 请求 CarLife 同值 | 两边一致才能直通；宽屏用 98311 的 `saveArea`/`needAdapterScreen` |
| `VideoBridge` | CarLife NAL → AA video 通道（**不重编码**） | 首帧/分辨率变化/会话重启重发 VideoConfig（SPS+PPS）；SPS `level_idc` 过高要改写；aa video ack 流控、写队列满时丢非关键帧 |
| `IdrPolicy` | 焦点恢复/重连后的 IDR | 缓存最近 IDR；空闲重发；4 s 零帧 → 请求 CarLife 引擎重建编码器（发 98315 RESET 再 98313？以实测为准）；**不要**自解码重编码 |
| `InputBridge` | AA InputReport → 9340 | 单点/多点映射；pointer index；坐标域=视频像素；旋钮→滑动/点击（可选） |
| `AudioBridge`（M5） | CarLife PCM → AA audio | 采样率跟随车机 audioConfig；停流 300 ms 内补静音；TTS 独立通道 |
| `FocusStateMachine` | AA 视频/音频焦点 ↔ CarLife pause/start | 倒车/原车菜单：暂停编码 + 恢复后立即 IDR；音频焦点同理 |
| `BridgeSession` | 两侧状态机 + 重连 | 任一侧重启：清 `configSent`、重发 config、等新 IDR；指数退避 1→2→4→8 s |

### 3.5 ui / diag

- 前台服务常驻 + 电池优化白名单引导（荣耀）；
- 页面：连接状态、日志（滚动+复制）、证书管理（导入 PEM/P12、显示指纹与到期）、导出 ZIP（含 App 日志、版本信息、配置快照）；

## 4. 台架与调试

### 4.1 台架 A：AARE 桌面车机（M2/M3 主用）

1. PC 装 JDK 17–21、adb、ffmpeg；
2. 解压 `aare-headunit-*.zip`，运行 `bin/aare-headunit`（Windows 用 Git Bash/WSL）；

4. 桌面车机连 `127.0.0.1:5277`（参数以 `aare-headunit --help` 为准）；
5. 它**不校验手机证书**（首次会要求 Trust 车机证书），自签即可；出画面后可在 `--headless DIR --script ...` 下做自动化截图。

### 4.2 台架 B：openauto（备选）

mretallack/AndroidAuto 的 Docker 方案：openauto headless + `adb reverse tcp:5000 tcp:5100`，手机 App 以 TCP client 连 `localhost:5000`。适合验证 AAP 细节。

### 4.3 台架 C：M1 专用（无需车机）

坐在车里，**只连蓝牙、不插 USB**：荣耀车联 → CarLife → 无线 WLAN 连接 → 停在"正在连接"（此状态下引擎监听 7 端口）。然后运行 App 的 M1 模式：连 `127.0.0.1:7240`，握手、收流、在本 App 预览窗口里解码上屏。跑通后再接 AA 层。

> 可替代：用 CarPToCarL 的 `scripts/carlife_hu_sim.py` 在 PC 上验证同类链路，帮助对照日志。

### 4.4 日志规范

- 统一 TAG：`AA2CL`（可加子 TAG：`AA2CL/USB`、`AA2CL/AAP`、`AA2CL/CL`、`AA2CL/BRIDGE`）；
- 关键事件（必须打）：六串、TLS 握手结果、认证状态码、版本协商结果、服务发现通道表、视频 config/首帧/IDR、触摸事件（含 pointer count）、CarLife 65538/65544/65642、崩溃；
- 文件日志：`files/aa2cl.log` 环形 2 MB + 关键事件单独留 200 条；导出 ZIP 带版本/证书指纹/配置。

## 5. 排错手册（症状 → 原因 → 处理）

### 5.1 USB / accessory

| 症状 | 可能原因 | 处理 |
|---|---|---|
| 插上完全没反应 | `<usb-accessory>` 过滤器不匹配（六串不对） | 用 AARE 日志/`adb shell dumpsys usb` 取六串；先放宽过滤再收敛 |
| 收到广播但 `openAccessory` 失败 | 权限未授予 / 荣耀 USB 用途弹窗 | 引导用户选「始终」；`hasPermission` 后再 open |
| 有 fd 但读写即断 | 车机在 AOA 后未进入 AA / VBUS 抖动 | 重连状态机；把断开当正常事件 |
| 被其他 App 抢 accessory | 荣耀车联/HiCar 抢广播 | 停用/卸载冲突 App 测试；确认选择框选本 App + 始终 |

### 5.2 AA 侧

| 症状 | 可能原因 | 处理 |
|---|---|---|
| `AUTH_COMPLETE status -3` | 车机拒绝手机证书 | 换 Google 证书（M4）；台架上检查是否误连了校验的车机 |
| `-24` | 证书过期 | 更新证书；做到期提醒 |
| TLS 直接断 | 车机挂断 / 证书不受信 | 记录 subject/issuer；换证书重试 |
| `no version request from head unit` | 车机没进 AA 协议（某些车型的兼容问题） | 换台架先验证协议；实车换连接顺序/重插 |
| 一直黑屏 | 没发 VideoConfig / 等待 IDR / 焦点未恢复 | 查日志：config 已发？IDR 已发？焦点状态？ |
| 花屏/绿屏 | SPS level 过高、分辨率不匹配、IDR 时机 | 改写 SPS；对齐分辨率；焦点恢复补 IDR |
| 触控位置偏 | 坐标域搞错（误用屏幕像素/做了二次缩放） | 按视频像素原样传；检查 margins |
| 连 30 s 左右断 | 缺 ping/keepalive、视频 ack 未回 | 补 ping 响应与 ack 流控 |

### 5.3 CarLife 侧

| 症状 | 可能原因 | 处理 |
|---|---|---|
| 7240 连不上 | 荣耀车联没进"正在连接" | 引导用户手动点无线连接并停留；重启 CarLife 引擎 |
| `65538` 不回 | 引擎状态不对 / 被 4.0 污染 | `am force-stop com.baidu.carlife.honor` 重启引擎；首次连接必须 3.0 |
| 收 `65642` | 进了加密鉴权路径 | 检查协议版本（3.0）与 `CONTENT_ENCRYPTION=0`；中止并重启引擎 |
| 无 `65544` | HU_INFO 字段序错 / 未主动推 98386、98311 | 对照字段表；主动推，不等手机 |
| 有 `65544` 但无画面 | 未发 98313 / 视频通道未建 / 引擎在 encoding 欢迎页 | 查 8240 是否来帧；检查是否手动"正在连接"（自动拉起只出欢迎页） |
| 能点不能拖 | 触控消息用错（单点消息无指针/动作码错位） | 用 0x68001 复合动作 + pointer index；检查 MOVE 走 0x68004 或复合动作 |
| 双指无效 | 走了单点消息 | 双指必须 0x68001 + `POINTER_DOWN/UP` + index |
| 音频无声/爆音 | 采样率不匹配、停流未补静音、通道未 INIT | 跟随车机采样率；补静音；检查 0x30001/0x30006 |
| 连上 20 s 后断开 | 内容加密握手未完成（65642） | 关闭 CONTENT_ENCRYPTION |
| 荣耀车联进不了"正在连接" | 车机蓝牙未连接 | 先连 MIB3 蓝牙（WLAN 引导页门槛） |

### 5.4 性能/稳定性

| 症状 | 处理 |
|---|---|
| 手机发热/掉帧 | 直通不重编码；降 fps/码率；避免边快充边满负载；M5 测温度曲线 |
| 长时间后断连 | 看门狗 + 重连；检查省电策略（荣耀后台限制） |
| 倒车后黑屏 | 焦点状态机 + 恢复 IDR |
| App 被系统杀 | 前台服务 + 电池优化白名单 + Honor 自启动设置 |

## 7. 代码规范与工程纪律

1. **状态机优先**：AA / CarLife / Bridge 三层各自状态机，所有跨线程只走有界队列；禁止在 UI 线程阻塞。
2. **版本锁**：CarLife 协议版本硬编码 3.0；CarLife+ App 版本记录并在 UI 显示；关键常量集中在一个 `CarLifeProtocol` 对象。
3. **日志即产品**：没有日志的排查等于瞎猜；关键事件必须落盘。
4. **小步提交**：每通过一个 checklist 项提交一次，commit message 用 `M1: 98311/65544 握手通过` 这种格式。
5. **不碰证书分发**：证书只放用户导入路径，不内置进 APK、不上传、不预置下载。
6. **开源合规**：vendor GPL 代码保持文件头；CarPToCarL MIT 部分保留 NOTICE；仓库根 LICENSE=GPL-3.0。
7. **车内调试**：停车操作；日志导出 ZIP；长时间测试注意手机温度。

## 附录 B：协议速查

### B.1 CarLife（荣耀 8.8.5 / versionCode 274）

- 端口：7240 主 / 8240 视频 / 9240 媒体 / 9241 TTS / 9242 VR / 9340 触控 / 9440 data
- 协议版本：3.0（`08 03 10 00`）；4.0 或 3.2+ → 加密鉴权 → 静默挂死 + 进程级污染
- 帧：控制通道 8B 头 `[u16 len][u16 rsv][u32 type]`；数据通道 12B 头 `[u32 len][u32 seq][u32 type]`；大端
- 关键消息：98305 / 65538 / 98343 / 65540 / 98307 / 98344 / 98386 / 65570 / 98311 / 65544 / 98313 / 131074 / 65642
- 触控：9340；0x68001 复合动作（双指必须），0x68002/3/4 单点，0x68008 硬键；VR 键在 8.8.5 上改用 0x10066（65638）
- 音频：9240 媒体（12B 头 + PCM，0x30001/0x30006…）、9241 TTS（0x40001/2/3）
- 昼夜：98424（`CarlifeThemeChange{themeModes}` 0 日 / 1 夜）
- 车 GPS：98320（25 字段，前 24 required）

### B.2 AA（公开资料）

- 传输：USB AOA v2（51/52/53 → `18D1:2D00`）
- TLS：1.2，手机=TLS server，双向认证；证书链 `[CarService, Google Automotive Link]`
- 认证状态：0 / -3 / -23 / -24（车机在 AUTH_COMPLETE 返回）
- 通道：video / input / media audio / speech audio / mic / sensor / bluetooth / phone status / navigation / media browser / notification / cluster
- 视频：H.264；首帧前 VideoConfig；焦点恢复等 IDR；ack 流控
- 输入：坐标域=视频像素；touch/key/rotary
